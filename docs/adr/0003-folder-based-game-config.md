# Games and instruments are defined by data folders, aggregated at build time, with behavior in a code-side Shape registry

The per-game `GameDefinition` modules (2,089 lines Genshin / 3,405 lines Sky) inline every instrument's label arrays, icons, note tables and midi ids — the named `*Kinds` building blocks exist but nothing references them (zero runtime consumers), so adding an instrument means hand-copying ~150 lines of arrays with no cross-checks. We decided each game becomes a self-contained folder (`src/lib/games/<id>/`): a `game.json` (identity incl. `storageId`, display/meta, features, settings, midi, Song Grid, tempo changers, **ordered** instrument list), a `presets.json` of named Note Presets, and one folder per instrument (`instruments/<Name>/`) holding its audio samples plus a `meta.json` — scalars, a **Shape id**, a sustain config, and `notes` as either a preset name or an inline array of per-note structs (`{file?, midi, baseNote, icon, loop?}`; `midi` is the Note Id, `file` defaults to `<index>.mp3`, per-note `loop` replaces the parallel `noteLoops` array). Everything is aggregated and zod-validated at build time into a normalized registry: an eager JSON-only metadata map of **all** games (service-worker-safe — it dissolves the `GameIdentity` DOM-free carve-out) plus the full definition (glyph components, shapes) for the active game via the `$game` alias; `PUBLIC_GAME` becomes the *default* game, so a future runtime game switch only needs the alias replaced with a lazy per-game glob. Behavior stays in code the data references by name: `shapes.ts` maps game-prefixed Shape ids to keyboard-arrangement implementations (common grids share one parameterized implementation; exotic future shapes get bespoke components) with their button component and Label Sets. Samples are overlay-copied to the locked `static/assets/audio/<id>/<Name>/` URLs (active game only per build — the other game's ~13 MB stops shipping). The runtime shape modernizes with it: notes are structs everywhere (5 consumer files), and the golden config fixture is regenerated alongside a kept equivalence test that derives the old parallel-array surface from the new config against the frozen old fixture.

## Considered Options

- **Runtime-fetched config (user-loadable instruments)** — rejected: the app is a fully prerendered static SPA with synchronous config consumers (`Instrument` constructor, module-eval derivations); async config would rearchitect all of it for an audience (end users) nobody asked to serve yet. Build-time aggregation doesn't preclude adding a runtime layer later.
- **Colocating `meta.json` with the audio in `static/`** — rejected: a game's definition stays split across two distant trees, and "add a game = add one folder" is never true.
- **`extends`/deep-merge defaults** — rejected: array-merge semantics are a footgun and value provenance requires walking a chain; named presets resolve in one hop. After Label Sets moved onto Shapes, only the notes table needed reuse at all.
- **Parameterized shape types (`{type: 'grid', columns: 7}`)** — rejected: the same geometry can need different behavior per game (framed Genshin buttons vs frameless Sky), and future instruments may need arbitrary arrangements; a named id per game keying into code branches keeps every shape independently implementable.
- **Deriving shape from note count at build time** — rejected: silently resurrects the `length → geometry` coupling being removed (the dead `len === 14` branch shows where that leads); the field is one line and is the point of the exercise.
- **Keeping the parallel-array runtime shape (authoring-only change)** — rejected: a permanent authoring↔runtime translation tax, and the struct model matches note-id-centric song identity (ADR-0001); only 5 files consume the old shape.

## Consequences

- Adding an instrument = create a folder, drop samples, write ~15 lines of `meta.json`; no code. Validation (zod at load + a vitest sweep) checks: every note's `file` exists, `notes.length` fits the Shape, icons exist in the game's glyph map, the Shape id is registered, and the `game.json` list matches folders — a folder absent from the list is an intentional **Unlisted Instrument** (the `Aurora_Short` case).
- Adding a game = create the folder + code only for what data can't express: one `GameId` union entry, `shapes.ts`, glyph components.
- `meta.json` carries an English `displayName` fallback; i18n overrides it when a locale has the key, so new instruments need zero locale edits.
- Label Sets leave instrument data entirely (Shape-owned); the five keyboard surfaces switch on the instrument's Shape and the `len === N → 'keyboard-N'` CSS classes die. Song-grid surfaces (composer canvas, sheet visualizer, VSRG) keep reading the game-level Song Grid.
- Note scales and CSS class names, byte-identical across games (music theory, not game data), move to shared core (~1,000 duplicated lines removed). The unreferenced `*_KINDS` exports and their fixture sections are deleted.
- Legacy `APP_NAME === 'Genshin'` remnants that duplicate existing config fields (default icon, animation delay) switch to reading the config during the consumer update.
- The historic cased `storageId` stays an explicit `game.json` field, never derived; new games set it equal to `id`.
