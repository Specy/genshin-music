# Songs store absolute Note Numbers; pitch settings are rewriting Basepoints

The v4/v3 formats stored the nominal id and kept pitch outside the note — a play-time playback-rate label — which left every surface translating between id spaces and made an all-notes piano-roll view impossible to state. We decided (2026-08-19) that every note in every format stores an **absolute MIDI Note Number on one shared axis, Basepoint included**: for **pitched buttons** the sounding pitch the listener hears (derived per button from `baseNote` at registry build — nearest chromatic match to the nominal, validated); for **assigned buttons** (`pitched: false` in config — percussion, SFX, and chord strums like Ukulele's G7 button) the button's Nominal Id carried by the Basepoint. Pitch settings (song-level plus per-track override) become **Basepoints**: changing one rewrites the affected tracks' numbers by the interval, stranded notes included. Switching a track's instrument rewrites button-preservingly through nominal correspondence (Lyre→Vintage-Lyre still re-flavors; cross-layout swaps strand as before), and cross-game conversion stays sound-preserving (carry, octave-fold, strand). Formats bump to composed v5 / recorded v4 / vsrg v3 with lazy upgrade on load; the compressed composer view keeps the Song Grid as its view function (off-scale notes render nearest-row with an accidental hint), while a future pure view renders the axis by linear scaling — the architecture is one absolute axis plus a view function per surface. Supersedes ADR-0001's song-side identity; Nominal Ids survive as the instrument/grid namespace, so ADR-0004/0005 hold under the new vocabulary.

## Considered Options

- **Nominal + folded Basepoint only** ("transposition-absolute") — rejected: bakes a known lie into the new format for tuned instruments (the roll shows D where the button's own label and the ear say Db), and upgrading to honesty later means migrating every song a second time.
- **No format change** (a future pure view derives the axis at render time) — rejected: pitch stays load-bearing at runtime forever, and "changing pitch moves notes" becomes a UI illusion instead of a format truth.
- **Sound-preserving instrument swap as the default** (pure DAW) — rejected: Lyre→Vintage-Lyre would strand D/E/A/B instead of re-flavoring them, killing behavior users rely on. May appear later as an explicit secondary choice.
- **Chord/SFX marking via a baseNote convention** — rejected: an identity class hidden inside a display string; a stray character silently flips a button's class instead of erroring. Explicit `pitched: false`; `baseNote` becomes a free display label ("G7").
- **Authoring explicit soundingMidi** — rejected: restates `baseNote` and can drift from it. Derivation plus build-time validation instead (a non-pitch-class `baseNote` on a pitched button is an error).
- **MIDI import preserving accidentals + auto-Basepoint detection** — deferred, not rejected: import keeps snapping to white keys for parity today; the format can host accidental-true import later with no further migration. (2026-08-21: the Basepoint half of that deferral was narrower than it read, and is closed. A file's midi numbers are absolute sounding pitches — that is what the honest export writes — so import now takes the layer's Basepoint OFF before snapping onto the grid and carries the snapped nominal back through that layer's own instrument (`nominalToNumber`). Export and import are inverses at any Basepoint; before, our own non-C export re-imported lifted twice, with distinct notes colliding onto one grid row. Still deferred: preserving accidentals, and INFERRING a Basepoint a file neither names in a key signature nor carries in our metadata.)

## Consequences

- `baseNote` is promoted from cosmetic label to load-bearing data: a one-time by-ear audit of the deviant instruments (Vintage-Lyre, Ukulele, LingeringEuphonia, the SFX set) precedes migration — this session already reclassified Ukulele/Euphonia's "second G" as a G7 chord button — and registry validation guards it afterwards.
- Basepoint changes and instrument swaps become real, undoable edits (they rewrite notes), no longer free label flips.
- Stranded Notes generalize: off-scale numbers between grid rows render nearest-row with an accidental hint; strands move with their track on Basepoint changes, pass through swaps, and can un-strand.
- Legacy decode gains one step (frozen tables → nominal → sounding); stranded pre-migration notes migrate best-effort as `id + Basepoint offset`. MIDI export becomes transposition-honest for the first time. `toOldFormat` export is deleted (kept as commented reference); old-format import stays.
- The id→button→id round-trips and the `MIDI_MAP_TO_NOTE`/`NOTE_MAP_TO_MIDI` tables retire.
- Third-party tools that read song JSON without checking `version` will misread v5/v4/v3 numbers as nominal ids.
