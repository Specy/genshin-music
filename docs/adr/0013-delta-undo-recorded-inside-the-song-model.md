# Delta undo, recorded inside the song model

The composer's undo used to be a tools-panel accessory: a full `song.clone()` per edit (every column and note deep-copied — the GC/perf complaint that started this), recording only while the panel was open, cleared on every panel toggle, with no redo. We decided to replace it with composer-wide undo/redo where **every `ComposedSong` mutator records its own typed reversal data (a delta) at the mutation site**, into a history that is attached to the song by the composer and absent everywhere else.

Recording lives inside the class rather than in a composer-side command layer for a reason that makes the alternative not merely worse but incorrect: the mutators have internal effects only the class knows about — `removeColumns`/`deleteColumns` run `normalizeSpans` (clamping surviving notes' spans) and `validateBreakpoints` (dropping breakpoints), `setInstrument` runs `rewriteForBasepoint` and `#mergeTrackDuplicates` (deleting notes) — so a call-site inverse either misses those or defensively captures broad before-state, which is the snapshot approach again. For the same reason, generic region before-patches were rejected: the heaviest ops (Basepoint change, instrument swap) touch every column, so a region patch degenerates to a full snapshot on exactly the ops that motivated the change. A parameter delta records them in O(1) — the rewrites are self-inverse under a negated interval.

## Consequences

- **Detached objects ride the history by reference, never cloned.** A mutator that splices notes/columns out hands the detached objects themselves to the delta; undo re-inserts them. Safe because history is strict LIFO and any new edit clears the redo stack, so nothing else can reach a detached object while it waits — and re-insertion restores object identity, which the composer's identity-holding gestures (sustain recordings) already expect to defend against, not depend on.
- **No history attached ⇒ no recording, by construction.** Deserialization, MIDI import, `toOtherGame`, player loads and clone/convert paths never attach one. The composer attaches a fresh history when it installs a song, which _is_ the clear-on-song-identity-change rule.
- **Every top-level song field write moved behind a method** (`setBpm`, `changeBasepoint`, `setReverb`, `rename`, …) so no edit exists outside the recorded surface; `selected` keeps its public setter as the one sanctioned non-edit (cursor) write. Compound gestures were promoted into single methods (`changeBasepoint` writes the pitch field _and_ rewrites the notes; the old caller applied the field first and passed both interval ends by hand). One public mutator = one Undo Step; a reentrant group API exists solely for gestures that span time (the Duration Hold).
- **Dirtiness is Savepoint-derived**, not an increment-only counter: undoing back to the last-saved position makes the song clean.
- **The merge-layer and remove-layer confirm dialogs were dropped**: they existed because those ops were irreversible, and now they are not.
- **Coverage is enforced structurally**: the test suite enumerates the class's callable surface and fails if any mutator lacks an undo/redo round-trip row (the `reactivePublish.test.ts` pattern), alongside randomized op-sequence walks asserting serialize-equality at every history position.
