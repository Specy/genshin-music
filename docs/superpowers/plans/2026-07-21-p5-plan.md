# Phase 5: PWA, Release Hygiene & Parity Exit — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the SvelteKit migration. The branch is already page-complete (P4c left zero `PageStub`s anywhere in `src/routes/`), so this phase ships the last runtime capability the port still lacks — the **service worker / PWA** — and then converts the branch from "all pages ported" into "releasable": root head/metadata parity, analytics + `PAGES_VERSIONS` final wiring, a real **bundle comparison against the old app**, README rewrite in all five languages, workflow modernization, a decided (not deferred) formatter/EOL policy, the spec §9.3 final audits, and the **full parity exit matrix** — every route, both games, storage keys diffed against the inventory, spec §13 success criteria run one by one.

**Architecture:** Same conversion discipline as every prior phase. Old React/Next blobs (`git show migration/next16-react19:<path>`) are the behavior specs; minimal-diff ports; every deviation disclosed with rationale; old quirks and bugs preserved and flagged, never silently fixed. Two genuinely new pieces of machinery land here:

1. **The service worker.** Old `src/service-worker.ts` was written against `@serwist/next` (which only supplied the `__SW_MANIFEST` injection point — the worker precached nothing). SvelteKit has a *native* service-worker entry (`src/service-worker.ts`, built by Vite into `${base}/service-worker.js`), so the port keeps the plain `serwist` library and drops the framework integration entirely (spec §6.6). Cache names, strategies, the `MAJOR_VERSION`-3 install branch and the custom activate-time GC all stay byte-identical so **installed PWAs update in place instead of losing their offline caches** (spec §5.3 / §11 risk row).
2. **`$game/identity`** — a tiny, dependency-free per-game module exporting `{id, storageId}`. The service worker needs `storageId` for its cache names but must NOT import `$core/legacyConfig` (that pulls `$game/index.ts`, which imports 11–14 `.svelte` glyph components into a worker bundle with no DOM). One literal per game, still inside the game folder, so the "adding game #3 = create `games/<id>/`" property (spec §5.5) holds.

Everything else in this phase is either a decision to be *made and recorded* (EOL policy, wrangler action versions, page-version bumps, analytics placement) or a verification pass. Where a decision is genuinely ambiguous the conservative parity-first option wins and is documented — the user pre-authorized autonomous continuation.

**Tech Stack:** TWO new devDependencies: `serwist` (old had exactly `serwist ^9.5.11` in `devDependencies`, plus `@serwist/turbopack`/`@serwist/next` which are NOT ported) and `rollup-plugin-visualizer` (spec §4.1's named replacement for `@next/bundle-analyzer`). No new runtime dependencies.

**Parent docs:** spec `docs/superpowers/specs/2026-07-19-sveltekit-migration-design.md` §6.6 (service worker), §4.2/§4.4 (prerender + routing), §9.3 (final audits), §10 Phase 5, §13 (success criteria); `docs/superpowers/audits/2026-07-19-storage-inventory.md` (byte-locked storage keys); ledger `.superpowers/sdd/progress.md`, blocks `=== P4c -> NEXT PHASE INPUTS ===` (Task-10 block + final-review rounds 1, 2 and 3 — every "P5 INPUTS" paragraph stands, they are cumulative not superseding). Base commit **`d22acdd3`** (`fix: P4c final-review fix wave review findings`) on branch `migration/sveltekit`.
